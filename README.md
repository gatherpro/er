# 今日だけ自動運転

**朝に決めて、あとは自動で進む。**

今日一日を分岐まで含めて自動運転。決断は朝だけ、実行は通知がやる。

## コンセプト

一行で言うと：**今日だけ自動運転。朝の一文で分岐つき1日を確定し、通知が強制トランジションで前へ進める。**

### タグライン

1. 朝に決めて、あとは自動で進む。
2. 今日一日、分岐まで含めて自動運転。
3. 決断は朝だけ、実行は通知がやる。

## 体験原則（5箇条）

1. **今日の一本路線**：ビューは"今日のライン"のみ。迷う分岐は裏で自動判定。
2. **朝の一文→即確定**：テンプレ＋自然言語で分岐を定義。当日は基本"タップのみ"。
3. **日次ダイヤル**：Gentle / Coach / Boss の強度を朝に一発決定（通知強度・スヌーズ・圧縮率・強制遷移が連動）。
4. **強制トランジション**：終了・超過・割込みで機械的に遷移。優先規則＝締切＞移動＞対人＞机作業。
5. **安全と可逆性**：常時"緊急停止"、その日のダイヤルは常に弱めに戻せる。ログは透明で後から見直せる。

## 日次ダイヤル仕様

### 🌱 Gentle（ゆるやかに）

- 通知最小限
- スヌーズ2回まで
- 超過時は分割して後段へ
- 柔軟な調整が可能

### 💪 Coach（ほどよくプッシュ）

- 段階的なナッジ
- スヌーズ1回まで
- 超過は10%圧縮＋分割
- バランスの取れた強度

### ⚡ Boss（強制的に進める）

- スヌーズ不可
- チェックリスト通過まで遷移不可
- 超過は最大30%圧縮＋即切上げ
- 締切厳守モード

## 主な機能

- **朝の一文入力**：今日の予定を自然な言葉で入力
- **テンプレート選択**：よく使う1日パターンを素早く適用
- **日次ダイヤル**：今日の強度（Gentle/Coach/Boss）を選択
- **今日のタイムライン**：1日の流れを一覧表示
- **強制トランジション**：通知による自動タスク切り替え
- **優先度自動判定**：締切＞移動＞対人＞机作業
- **緊急停止**：いつでも全通知を停止可能
- **🔀 分岐設定**：条件による自動ルート選択
  - **時刻チェック分岐**：特定の時刻を基準に自動分岐
  - **完了状態分岐**：他のタスクの完了状況で分岐
  - **手動選択分岐**：その場で選択肢を選んで分岐
- **チェックリスト**：Bossモードで必須項目を確認
- **スヌーズ機能**：ダイヤルに応じて通知を遅延

## 使い方

### 基本フロー

1. **朝の入力**
   - アプリを起動
   - 今日の予定を一文で入力（または テンプレート選択）
   - 例：「午前は資料作成、午後はミーティング3つ、夕方から移動」

2. **ダイヤル選択**
   - 今日の強度（Gentle/Coach/Boss）を選択
   - 通知強度、スヌーズ回数、超過時の挙動が連動

3. **自動実行**
   - 「今日のライン」が表示される
   - 予定時刻に通知が届く
   - タスク完了タップまたは時間経過で自動遷移

4. **緊急停止**
   - 右下の赤いボタンで即座に停止
   - すべての通知が止まる
   - 再開ボタンで復帰可能

### テンプレート

以下のテンプレートが利用可能：

**基本テンプレート**
- **標準作業日**：メール→資料作成→MTG→まとめ
- **締切集中日**：締切案件に特化した構成
- **移動日**：移動時間を考慮したスケジュール
- **ミーティング多め**：MTG中心の1日
- **クリエイティブ集中**：ディープワーク重視

**分岐テンプレート**（🔀 分岐機能のデモ）
- **時刻チェック分岐**：12時前後で自動的にランチプランが変わる
- **手動選択分岐**：外食か社食かをその場で選択
- **完了状態分岐**：レビュー結果に応じてリリースor修正に分岐

### 🔀 分岐機能の詳細

**分岐を前提に設計された今日専用エンジン**という差別化ポイントを実現する3つの分岐タイプ：

#### 1. 時刻チェック分岐
指定した時刻を基準に自動で次のタスクを選択します。

**使用例**：
- 「午前の作業」を12時前に終えたら「ゆっくりランチ（90分）」
- 12時以降に終えたら「短めランチ（45分）」

**仕組み**：タスク完了時に現在時刻をチェックし、条件に応じて自動分岐。

#### 2. 完了状態チェック分岐
他のタスクの完了状況を見て次のルートを決定します。

**使用例**：
- 「レビュー待機」後、レビューが完了していれば「リリース準備」へ
- レビューが未完なら「修正作業」へ

**仕組み**：特定のタスクIDの完了状態をチェックして分岐。

#### 3. 手動選択分岐
その場でモーダルが表示され、ユーザーが選択肢を選びます。

**使用例**：
- 「午前の作業」後、「外食する」か「社食にする」かを選択
- 選択に応じて異なる所要時間のランチタスクへ

**仕組み**：タスク完了時に選択肢モーダルが表示され、ユーザーの選択で次のタスクが決定。

#### 分岐の利点

- **迷わない**：朝の段階で「もし〇〇なら△△する」を決めておける
- **柔軟**：状況に応じて自動的に最適なルートへ
- **可視化**：タイムラインで「🔀 分岐あり」と表示されるので事前に把握できる
- **複雑な1日も対応**：割込み、遅延、条件変化に強い
